# M7.2 — Thought rescoping

**Status:** DESIGN APPROVED 2026-11-06 — operator rulings recorded below; the immutability contract in DESIGN.md §10 is amended concurrently with this document. Not yet implemented; implementation follows the plan-before-code flow.

**One-line:** Re-file an existing thought under a different scope through supervised paths — a `kengram rescope` CLI subcommand and a `rescope_thought` MCP tool — each atomically appending an audit row to a new append-only `scope_changes` table, under a reclassified contract: `scope` is operational metadata, not claim content.

## Design pivot — the class taxonomy the schema never named

The schema has three kinds of column and the docs only ever named two of them:

| Class | Columns | Mutability under the current contract |
|---|---|---|
| **Raw claim** | `content`, `source`, `created_at` | Immutable — the single source of truth all derived signals are recomputed from (§10) |
| **Derived signal** | `tags` + provenance triplet, `embeddings` | Overwritten freely — recomputable from raw text, no audit trail needed (§6.5, §10) |
| **Write-time asserted metadata** | `scope` (and `metadata`) | Never adjudicated — 0003's comment swept `scope` into "claim content" as boundary-drawing in the retraction fight, not as a theory of scope |

The adjudication this milestone records: **`scope` belongs to the third class and is mutable.** The argument:

1. **The capture default weakens the intent claim.** `capture` defaults `scope` to `global` when the caller omits it (`kengram-mcp/src/capture.rs`). A defaulted or first-guess label is a weak assertion; reclassifying it later is housekeeping, not revisionism.
2. **The dotted convention exists because taxonomies evolve.** `work.tcgplayer` presumes renaming/merging/retiring labels over time. Yet the schema gives scope zero hierarchy semantics (prefix-matching lives in search only) — that's a filing-drawer shape, not a claim-content shape.
3. **Nothing consumes the original value.** Retrieval filters, `list_scopes`, the web scope-browser, and stats all read the live value. No code path or dogfood workflow needs "what scope did the agent file this under in 2026-05"; the mutability of `content` is load-bearing because content *is* the record. Scope isn't.
4. **The mutation is already possible.** `psql` is the sanctioned write/admin interface (CLAUDE.md). `UPDATE thoughts SET scope = ...` runs today, silently, skipping every safety step. The invariant has never been enforced — only not offered. A supervised command is harm reduction: it adds exactly what raw SQL skips (atomic audit + tag requeue).
5. **Tags are the precedent.** The system already rewrites the entire organizational layer (`tags` JSONB) in place, routinely, with no audit — because tags are derived. Scope is asserted rather than derived, so it gets what asserted-but-mutable mutations get elsewhere in this codebase: a durable trail (retraction's `retracted_at`/`reason`; `migration_audit`; `thought_links` soft-delete).

**Audit shape — Pattern B (event table), not Pattern A (state-flip column).** The M3 retraction pattern (`retracted_at` on the row) records one hop; rescoping is repeatable by design (`work.foo` → `work.bar` → `personal.bar`), and a `scope_original` column would clobber on the second hop or block it. The 0010 `migration_audit` precedent — append-only, one row per event — fits repeat rescopes and subtree renames naturally, and is no more work.

**What stays immutable:** `content`, `source`, `created_at`. `metadata` remains the ambiguous JSONB it already is — unadjudicated, untouched by this milestone.

## The amended contract (canonical wording)

Reused verbatim in DESIGN.md §10 and CLAUDE.md:

> `thoughts.content`, `source`, and `created_at` are immutable — the claim, its provenance, and its timestamp. `scope` is **operational metadata**: mutable only through the supervised rescope paths (`kengram rescope`, `rescope_thought`), each of which atomically appends an audit row to the append-only `scope_changes` table. Ad-hoc `UPDATE`s to claim columns remain outside the design; `psql` remains the operator escape hatch, as ever.

Dated history is **not** rewritten: migration 0003's comment ("immutability of the claim content (`content`, `scope`, …)") stays verbatim as a historical artifact — applied migrations are checksum-frozen, and the 2026-05-25 rename set the precedent that dated records stay honest. This document is the override record.

## In scope

- **Migration `0012_thought_rescoping.sql`** — the `scope_changes` table (below) + indexes + the house-rule `INSERT INTO migration_audit` seeding row (M5.2 convention).
- **Storage helpers** — `rescope_thought(pool, thought_id, new_scope, source, reason)` and `rename_scope_subtree(pool, old_prefix, new_prefix, source, reason)`, each a single-transaction bundle of the four effects below.
- **Orchestrator** — new `rescope.rs` in `kengram-mcp` mirroring `retract.rs` (request/response structs, `thiserror` enum, not-found distinction); shared by CLI and MCP tool, same seam-discipline as `finalize` so both surfaces behave identically.
- **CLI** — `kengram rescope` subcommand: single-thought form, dotted-boundary subtree rename, `--dry-run`, `--reason`.
- **MCP tool** — `rescope_thought`; `SERVER_INSTRUCTIONS` extension + regression pin test (M5 precedent).
- **Tag requeue** — every live rescope enqueues the thought's tag job (idempotent; `pending_tags` PK handles repeats) so derived tags re-condition under the new scope.
- **Retracted thoughts are rescopable** — filing hygiene; retrieval filters them regardless, and `get_thought`-by-ID remains the audit path.

## Out of scope (deferred)

- **Web write routes** — M8 stands: the web surface never writes. Rescoping is CLI + MCP only.
- **Synchronous re-tagging** — rescopes *enqueue*; the worker's tag drainer handles them on its normal tick. No new scheduling logic in kEngram (§11).
- **Tier 2 token-scope interaction** — a token locked to `work.*` calling `rescope_thought` across the boundary. Recorded under Open questions; folds into the Tier 2 auth work item.
- **Scope lifecycle** — orphaned-scope cleanup, `scopes` registry table, history compaction. Possibly never needed.

## Schema impact (migration 0012 draft)

```sql
-- M7.2: append-only audit trail for thought rescoping. Written only by the
-- rescope storage helpers; never updated, never deleted. One row per
-- (thought, scope change) event — repeat rescopes append, they do not
-- overwrite (contrast: a state-flip column would record only the last hop).
CREATE TABLE scope_changes (
    id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    thought_id  UUID        NOT NULL REFERENCES thoughts(id) ON DELETE CASCADE,
    old_scope   TEXT        NOT NULL,
    new_scope   TEXT        NOT NULL,
    changed_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    source      TEXT        NOT NULL CHECK (source IN ('cli','mcp')),
    reason      TEXT
);

-- Audit-path lookup ("has this thought been re-filed?") and recent-changes
-- diagnostics, mirroring migration_audit's ran_at DESC pattern.
CREATE INDEX scope_changes_thought_idx
    ON scope_changes (thought_id, changed_at DESC);
CREATE INDEX scope_changes_changed_at_idx
    ON scope_changes (changed_at DESC);

-- House rule (M5.2): every row-touching migration seeds its audit row.
INSERT INTO migration_audit (migration, rows_touched, notes) VALUES
    ('0012_thought_rescoping', 0,
     'Created scope_changes append-only audit table. Reclassifies thoughts.scope as mutable operational metadata (docs/milestones/m7.2-thought-rescoping.md). No thoughts rows touched.');
```

`ON DELETE CASCADE` is consistent with the schema's posture: thought rows are effectively never deleted (retraction is the removal), and the cascade exists for psql-emergency parity with `thought_links`.

## The four effects — one transaction

Every live rescope does, atomically:

1. **Conditional `UPDATE`** scoped to the old value — re-running an identical rescope matches zero rows, so the operation is idempotent by construction and the orchestrator can report no-op vs. did-work (the `retract_thought` / `unlink_thoughts` three-way precedent).
2. **Audit insert** from the `UPDATE ... RETURNING id, scope` set — one `scope_changes` row per moved thought, carrying `source` (`cli`/`mcp`) and optional `reason`.
3. **Tag requeue** per changed thought via the existing `enqueue_tag_job` (`pending_tags`, PK idempotent). Rationale: the tagger conditions on per-scope established-tag vocab (M4.1 `ScopeVocab` hint) and the finalize seam strips entities matching the thought's own scope / known scopes (`filters.rs::strip_scope_identifiers`) — tags generated under old-scope context are silently stale against the new one.
4. **Commit.** Embeddings are untouched — they never read scope.

## CLI surface delta

```
kengram rescope --thought <id> --to <scope> [--reason "..."]
kengram rescope --scope <old> --to <new> [--reason "..."] [--dry-run]
```

- **Subtree semantics:** `--scope work.foo` matches `work.foo` exactly and every `work.foo.*` on a **dotted boundary** — `work.foobar` is never touched. The predicate is `scope = $1 OR scope LIKE $1 || '.%' ESCAPE '\'`; free-form scope names can contain LIKE metacharacters (`%`, and `_` as a single-char wildcard — `personal_medical` would otherwise wildcard-match), so the literal prefix must be escaped before binding.
- **Subtree mapping:** `old` → `new`, and `old.rest` → `new || '.rest'`. Resulting scopes are validated per-row through `Scope::new` (non-empty, ≤ 256 chars); any overflow aborts the whole transaction — a rename is all-or-nothing.
- **`--dry-run`** prints the matched thoughts and their old→new scopes and commits nothing.
- **`reason`** is optional on both forms (open question: require it for subtree renames, where the blast radius is N rows).

## MCP surface delta

```
rescope_thought(thought_id: uuid, scope: string, reason?: string)
  -> { thought_id, previous_scope, new_scope, changed }
```

- `changed: false` when already at target (no-op, no audit row); `Err(NotFound)` for unknown ids — same no-op/did-work seam as `retract_thought`.
- Bulk subtree rename stays **CLI-only**: it's operator taxonomy maintenance, not an agent workflow.
- This is the first **retroactive agent-facing write to an existing thought row since `retract_thought` (M3)**. Retraction flips a trust flag; rescope writes a claim-adjacent (but reclassified) column with a trail. `SERVER_INSTRUCTIONS` gains one sentence: correct filing at capture time is still preferred; rescope is for taxonomy drift, and the trail makes agent-initiated rescopes visible to the operator.
- All args are scalars — no `Option<serde_json::Value>` trap (the v7 schema-strip lesson doesn't apply).

## Crate structure delta

- **`kengram-storage`** — `rescope_thought` + `rename_scope_subtree` helpers; `RescopeOutcome` row-count return.
- **`kengram-mcp`** — new `rescope.rs` orchestrator; `server.rs` tool registration + `SERVER_INSTRUCTIONS` + pin test.
- **`kengram-cli`** — `Rescope` subcommand (wiring precedent: `backup.rs`'s standalone module).
- **`kengram-core`** — none. `Scope` already exists; outcome types live with storage.
- **No config delta.** Tag requeue uses the already-configured tagger model id (same resolution as `capture`).

## Derived-layer impact

- **Embeddings / retrieval:** none — the vector and trigram legs never read scope; `scope`/`scope_prefix` filters see the new value immediately after commit.
- **`list_scopes` / `stats` / web scope-browser:** live aggregates over `thoughts.scope`; counts migrate with the rows, zero changes.
- **Tag vocab conditioning:** per-scope top-N vocab shifts live for both old and new scopes — that's live re-derivation working as designed, not staleness. The staleness that *is* real (existing tags on the moved thought) is fixed by the requeue.

## Dependencies

- **M3** (retraction) — state-flip precedent, no-op/did-work seam, audit-by-direct-lookup pattern.
- **M4.1** (scope vocab) — the mechanism that makes tags scope-conditional, hence the requeue requirement.
- **M5.2** (`migration_audit`, soft-delete three-way status) — the append-only audit precedent and the no-op reporting grammar.
- **M6.0** (`kengram stats`) — the verification surface for "counts moved as expected".

## Success criteria

1. **Single rescope round-trip.** `kengram rescope --thought <id> --to work.bar` moves the thought; exactly one `scope_changes` row appears (`source='cli'`, reason recorded); a re-run reports no-op and adds no rows.
2. **Subtree rename.** `--scope work.foo --to work.bar` moves `work.foo` and `work.foo.baz`, never `work.foobar`; one audit row per moved thought; `--dry-run` commits nothing. A scope name containing `_` proves the ESCAPE clause works.
3. **Tag re-conditioning.** After the worker drains, the moved thought's `tags_extractor_*` provenance refreshes, and `strip_scope_identifiers` now strips the *new* own-scope identifier from entities (spot-check a thought whose old-scope name appears as an entity).
4. **MCP parity.** `rescope_thought` returns `changed: false` at target and a clean not-found error otherwise; `/api` reads of the same thought (via `get_thought` orchestrators) match the MCP view.
5. **Operator-visible movement.** `kengram stats` per-scope summary and `list_scopes` reflect the rename; a emptied old scope disappears from `list_scopes`.
6. **The contract holds in code.** The only `UPDATE thoughts SET` touching `scope` anywhere in the workspace is inside the two rescope helpers; no code path writes `content`/`source`/`created_at`. (Grep + review at implementation.)

## Open questions

- **`get_thought` / web-detail surfacing.** The retraction precedent says the audit path should surface the change — options: a `rescoped_at` + prior-scope hint on the thought shape, vs. full history staying SQL-only (like `migration_audit`). Leaning: surface "last rescope" metadata, keep history in SQL.
- **Tier 2 interaction.** Should a token locked to `work.*` be allowed to `rescope_thought` a `personal.*` thought? Today scope restrictions govern reads, not writes. Defer to the Tier 2 auth milestone, but the answer must land before Tier 2 ships.
- **`reason` policy.** Optional everywhere, or required for subtree renames (blast radius)?
- **`metadata` column.** Same third class as scope, but it feeds the finalize seam (`metadata.decision_type` override) and nothing rules on its mutability. Explicitly left unadjudicated here — worth a ruling before any future tool touches it.
