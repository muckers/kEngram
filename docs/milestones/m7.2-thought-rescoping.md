# M7.2 — Thought rescoping

**Status:** DESIGN APPROVED 2026-11-06 — operator rulings recorded below; the immutability contract in DESIGN.md §10 is amended concurrently with this document. Not yet implemented; implementation follows the plan-before-code flow.

**One-line:** Re-file an existing thought under a different scope through supervised paths — a `kengram rescope` CLI subcommand and a `rescope_thought` MCP tool — each atomically appending an audit row to a new append-only `scope_changes` table, under a reclassified contract: `scope` is operational metadata, not claim content.

## Design pivot — the class taxonomy the schema never named

The schema has three kinds of column and the docs only ever named two of them:

| Class | Columns | Mutability under the current contract |
|---|---|---|
| **Raw claim** | `content`, `source`, `created_at` | Immutable — the single source of truth all derived signals are recomputed from (§10) |
| **Derived signal** | `tags` + provenance triplet, `embeddings` | Overwritten freely — recomputable from raw text, no audit trail needed (§6.5, §10) |
| **Write-time asserted metadata** | `scope` (and `metadata`) | Never adjudicated — 0003's comment swept `scope` into "claim content" as boundary-drawing in the retraction fight, not as a theory of scope |

The adjudication this milestone records: **`scope` belongs to the third class and is mutable.** The argument:

1. **The capture default weakens the intent claim.** `capture` defaults `scope` to `global` when the caller omits it (`kengram-mcp/src/capture.rs`). A defaulted or first-guess label is a weak assertion; reclassifying it later is housekeeping, not revisionism.
2. **The dotted convention exists because taxonomies evolve.** `work.tcgplayer` presumes renaming/merging/retiring labels over time. Yet the schema gives scope zero hierarchy semantics (prefix-matching lives in search only) — that's a filing-drawer shape, not a claim-content shape.
3. **Nothing consumes the original value.** Retrieval filters, `list_scopes`, the web scope-browser, and stats all read the live value. No code path or dogfood workflow needs "what scope did the agent file this under in 2026-05"; the immutability of `content` is load-bearing because content *is* the record. Scope isn't.
4. **The mutation is already possible.** `psql` is the sanctioned write/admin interface (CLAUDE.md). `UPDATE thoughts SET scope = ...` runs today, silently, skipping every safety step. The invariant has never been enforced — only not offered. A supervised command is harm reduction: it adds exactly what raw SQL skips (atomic audit + tag requeue).
5. **Tags are the precedent.** The system already rewrites the entire organizational layer (`tags` JSONB) in place, routinely, with no audit — because tags are derived. Scope is asserted rather than derived, so it gets what asserted-but-mutable mutations get elsewhere in this codebase: a durable trail (retraction's `retracted_at`/`reason`; `migration_audit`; `thought_links` soft-delete).

**Audit shape — Pattern B (event table), not Pattern A (state-flip column).** The M3 retraction pattern (`retracted_at` on the row) records one hop; rescoping is repeatable by design (`work.foo` → `work.bar` → `personal.bar`), and a `scope_original` column would clobber on the second hop or block it. The 0010 `migration_audit` precedent — append-only, one row per event — fits repeat rescopes and subtree renames naturally, and is no more work.

**What stays immutable:** `content`, `source`, `created_at`. `metadata` remains the ambiguous JSONB it already is — unadjudicated, untouched by this milestone.

**This reverses a recorded decision.** The 2026-06-02 deferral record (corpus thought `940d3ffc`) captured the earlier YAGNI call that rescoping wasn't worth building. When this milestone's decision record is captured into kEngram itself, it should carry a `replaces` or `refines` link to `940d3ffc`, so the flip is visible in the link graph as well as in this doc.

## The amended contract (canonical wording)

Reused verbatim in DESIGN.md §10 and CLAUDE.md:

> `thoughts.content`, `source`, and `created_at` are immutable — the claim, its provenance, and its timestamp. `scope` is **operational metadata**: mutable only through the supervised rescope paths (`kengram rescope`, `rescope_thought`), each of which atomically appends an audit row to the append-only `scope_changes` table. Ad-hoc `UPDATE`s to claim columns remain outside the design; `psql` remains the operator escape hatch, as ever.

Dated history is **not** rewritten: migration 0003's comment ("immutability of the claim content (`content`, `scope`, …)") stays verbatim as a historical artifact — applied migrations are checksum-frozen, and the 2026-05-25 rename set the precedent that dated records stay honest. This document is the override record.

## In scope

- **Migration `0012_thought_rescoping.sql`** — the `scope_changes` table (below) + indexes + the house-rule `INSERT INTO migration_audit` seeding row (M5.2 convention).
- **Storage helpers** — `rescope_thought` and `rename_scope_subtree`, each a single-transaction bundle of the four effects below, with **every statement running on the `Transaction<'_, Postgres>`** — including the tag requeue. The existing `enqueue_tag_job(&PgPool, …)` cannot participate as-is; generalize it to `impl PgExecutor` or write the enqueue inline on the tx.
- **Orchestrator** — new `rescope.rs` in `kengram-mcp` mirroring `retract.rs` (request/response structs, `thiserror` enum, not-found distinction); shared by CLI and MCP tool, same seam-discipline as `finalize` so both surfaces behave identically.
- **CLI** — `kengram rescope` subcommand: single-thought form, dotted-boundary subtree rename, `--dry-run`, `--reason`.
- **MCP tool** — `rescope_thought`; `SERVER_INSTRUCTIONS` extension + regression pin test (M5 precedent).
- **Tag requeue (live thoughts only)** — every rescope of a non-retracted thought enqueues its tag job (idempotent; `pending_tags` PK handles repeats) so derived tags re-condition under the new scope. Retracted thoughts get the audit row but **no** requeue: the drainer doesn't filter `retracted_at`, and retracted tags feed neither the scope vocab nor `list_scopes`, so requeueing them just burns tagger calls.
- **Retracted thoughts are rescopable** — filing hygiene; retrieval filters them regardless, and `get_thought`-by-ID remains the audit path.

## Out of scope (deferred)

- **Web write routes** — M8 stands: the web surface never writes. Rescoping is CLI + MCP only.
- **Synchronous re-tagging** — rescopes *enqueue*; the worker's tag drainer handles them on its normal tick. No new scheduling logic in kEngram (§11).
- **Tier 2 token-scope interaction** — a token locked to `work.*` calling `rescope_thought` across the boundary. Recorded under Open questions; folds into the Tier 2 auth work item.
- **Scope lifecycle** — orphaned-scope cleanup, `scopes` registry table, history compaction. Possibly never needed.
- **Tag-queue priority** — rescope requeues land at `NOW()`, which puts them behind whatever was already queued and **ahead of every later capture** (`fetch_pending_tag_jobs` claims oldest-first). The structural fix is claim-order priority in `pending_tags` — the same mechanism the M9 review flags for artifact re-ingest — not a rescope-local hack. See *Queue cost* below.

## Schema impact (migration 0012 draft)

```sql
-- M7.2: append-only audit trail for thought rescoping. Written only by the
-- rescope storage helpers; never updated, never deleted. One row per
-- (thought, scope change) event — repeat rescopes append, they do not
-- overwrite (contrast: a state-flip column would record only the last hop).
CREATE TABLE scope_changes (
    id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    thought_id  UUID        NOT NULL REFERENCES thoughts(id) ON DELETE CASCADE,
    old_scope   TEXT        NOT NULL,
    new_scope   TEXT        NOT NULL,
    changed_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    -- actor follows the thoughts.source convention (free text: 'manual',
    -- 'agent:claude-code'). Transport is not identity: a CHECK-constrained
    -- 'cli'/'mcp' would make every agent indistinguishable, and the trail's
    -- reason for existing is naming WHICH agent moved a thought (the
    -- 2026-06-17 decision-record misfiled-write case).
    actor       TEXT        NOT NULL,
    reason      TEXT
);

-- Audit-path lookup ("has this thought been re-filed?") and recent-changes
-- diagnostics, mirroring migration_audit's ran_at DESC pattern.
CREATE INDEX scope_changes_thought_idx
    ON scope_changes (thought_id, changed_at DESC);
CREATE INDEX scope_changes_changed_at_idx
    ON scope_changes (changed_at DESC);

-- House rule (M5.2): every row-touching migration seeds its audit row.
INSERT INTO migration_audit (migration, rows_touched, notes) VALUES
    ('0012_thought_rescoping', 0,
     'Created scope_changes append-only audit table. Reclassifies thoughts.scope as mutable operational metadata (docs/milestones/m7.2-thought-rescoping.md). No thoughts rows touched.');
```

`ON DELETE CASCADE` is consistent with the schema's posture: thought rows are effectively never deleted (retraction is the removal), and the cascade exists for psql-emergency parity with `thought_links`.

## The four effects — one transaction

Every live rescope runs as **one `sqlx::Transaction`**. (An earlier draft of this section sketched a single-statement CTE chain; it was dropped — it computes new scopes inside SQL, leaving no place for the Rust `Scope::new` validation gate, and it obscured that `UPDATE ... RETURNING` on PG 16 yields the *new* row, `RETURNING OLD.*` being PG 18+. The pre-read carries the old values, so the pattern is version-agnostic.)

1. **Locking pre-read, materialized in Rust** — `SELECT id, scope AS old_scope, retracted_at FROM thoughts WHERE <predicate> FOR UPDATE`.
   - **Single-thought form:** the predicate is `id = $1` **alone** — never `AND scope <> $2`, which collapses no-op and not-found into the same zero-row answer while the MCP contract promises to distinguish them. Rust compares the result: no row → `NotFound`; `old_scope == target` → no-op (`changed: false`, nothing written); otherwise proceed.
   - **Subtree form:** the predicate is `scope = $raw OR scope LIKE $escaped || '.%' ESCAPE '\'` — **two bound parameters**. `$raw` also feeds the mapping offset (`substring(old FROM length($raw) + 1)`); `$escaped` doubles the prefix's backslashes first, then escapes `%` and `_`. One parameter cannot serve both jobs: a scope containing `_` or `%` gets either the wrong match set or the wrong substring offset. Zero matched rows = no-op, reported as such (the `retract_thought` / `unlink_thoughts` no-op/did-work precedent).
2. **Guard rejections, up front, before any write.**
   - `--to` equal to `--scope` → usage error; without it the "update" succeeds and writes audit rows with `old_scope = new_scope` — fake history.
   - Subtree form only: reject when `--to` **is `--scope` or lies inside its subtree** (`work → work.archive` moves `work.x` to `work.archive.x`, and every re-run re-matches it — `work.archive.archive.x` — fresh audit rows each pass, breaking this doc's re-run-is-a-no-op guarantee). The single-thought form has no self-nesting hazard: once moved, the thought's own scope no longer matches any re-run target.
   - Then compute each row's new scope **in Rust** (`old` → `new`, `old.rest` → `new.rest`) and validate it through `Scope::new` (non-empty, ≤ 256 chars). Any invalid row → rollback; the rename is all-or-nothing. This validation gate is exactly why the flow is not a single SQL statement.
3. **Update + audit + requeue — same transaction.** All three run on the `Transaction<'_, Postgres>`, never on the pool — which is why `enqueue_tag_job(&PgPool, …)` can't be reused as-is. Audit rows are written from the pre-read pairs, so `old_scope` is the true pre-update value regardless of Postgres version:
   - `UPDATE thoughts t SET scope = v.new_scope FROM (VALUES …) v WHERE t.id = v.id`
   - `INSERT INTO scope_changes (thought_id, old_scope, new_scope, actor, reason) VALUES …` — one row per moved thought, from the pre-read pairs
   - tag-job inserts into `pending_tags` (ON CONFLICT DO NOTHING semantics), **live thoughts only** (`retracted_at IS NULL` from the pre-read). Rationale: the tagger conditions on per-scope established-tag vocab (M4.1 `ScopeVocab` hint) and the finalize seam strips entities matching the thought's own scope / known scopes (`filters.rs::strip_scope_identifiers`) — tags generated under old-scope context are silently stale against the new one.
4. **Commit.** Embeddings are untouched — they never read scope. `FOR UPDATE` in the pre-read matters even single-user: two concurrent rescope calls must not both see the pre-move state and double-write audit rows.

### Queue cost

Requeued jobs land at `enqueued_at = NOW()`: behind anything already queued, but **ahead of every later capture** (oldest-first claim). On the live corpus this is concrete — the `rjf.tech` subtree is ~276 thoughts, so a rename of it parks ~27 hours of tagger backlog at daytime CPU-tagging speed (p50 ≈ 353 s/call), or ~2.8 h inside the nightly GPU window (≈ 36 s/call; `docs/linux-autostart.md`, "Optional: nightly GPU tagger window"). Therefore: `--dry-run` **must** print the requeue count alongside the match count, and the CLI should warn when the count is large ("this parks ~N h of backlog — consider timing it before the nightly tagger window"). The structural fix (priority in claim ordering) is the M9-flagged `claim_pending` priority work, explicitly not solved here.

## CLI surface delta

```
kengram rescope --thought <id> --to <scope> [--reason "..."]
kengram rescope --scope <old> --to <new> [--reason "..."] [--dry-run]
```

- **Subtree semantics:** `--scope work.foo` matches `work.foo` exactly and every `work.foo.*` on a **dotted boundary** — `work.foobar` is never touched. The predicate is `scope = $1 OR scope LIKE $1 || '.%' ESCAPE '\'`; free-form scope names can contain LIKE metacharacters (`%`, and `_` as a single-char wildcard — `personal_medical` would otherwise wildcard-match), so the literal prefix must be escaped before binding — and escaping means escaping the escape character `\` itself first, not just `%` and `_`.
- **Subtree mapping:** `old` → `new`, and `old.rest` → `new.rest`. New scopes are computed and validated per-row **in Rust** through `Scope::new` (non-empty, ≤ 256 chars) off the pre-read, before any write; any overflow aborts the whole transaction — a rename is all-or-nothing. See *The four effects*.
- **Self-equal / self-nesting guards:** `--to` equal to `--scope` is rejected in both forms; in subtree mode, `--to` anywhere inside the `--scope` subtree is rejected too (re-runs of such a rename re-match their own output and nest forever). Usage errors, nothing written.
- **`--dry-run`** prints the matched thoughts and their old→new scopes, **plus the tag-requeue count**, and commits nothing.
- **`--actor <id>`** — audit rows carry a free-text actor following the `thoughts.source` convention; the CLI defaults to `manual`.
- **`reason`** is optional on both forms (open question: require it for subtree renames, where the blast radius is N rows).

## MCP surface delta

```
rescope_thought(thought_id: uuid, scope: string, reason?: string, actor?: string)
  -> { thought_id, previous_scope, new_scope, changed }
```

- `changed: false` when already at target (no-op, no audit row); `Err(NotFound)` for unknown ids — same no-op/did-work seam as `retract_thought`.
- **`actor`** follows the `capture(source)` convention: the calling agent names itself (`agent:claude-code`), falling back to `mcp` when it doesn't. Transport (`mcp`/`cli`) is deliberately **not** the identity column — the trail has to answer *which* agent moved a thought, which the 2026-06-17 decision-record misfiled-write case makes concrete.
- Bulk subtree rename stays **CLI-only**: it's operator taxonomy maintenance, not an agent workflow.
- This is the first **retroactive agent-facing write to an existing thought row since `retract_thought` (M3)**. Retraction flips a trust flag; rescope writes a claim-adjacent (but reclassified) column with a trail. `SERVER_INSTRUCTIONS` gains one sentence: correct filing at capture time is still preferred; rescope is for taxonomy drift, and the trail makes agent-initiated rescopes visible to the operator.
- All args are scalars — no `Option<serde_json::Value>` trap (the v7 schema-strip lesson doesn't apply).

## Crate structure delta

- **`kengram-storage`** — `rescope_thought` + `rename_scope_subtree` helpers, every statement tx-scoped (`Transaction<'_, Postgres>`); `RescopeOutcome` row-count return. Generalizing `enqueue_tag_job` (currently `&PgPool`) to `impl PgExecutor` is in scope here — the requeue must join the transaction.
- **`kengram-mcp`** — new `rescope.rs` orchestrator; `server.rs` tool registration + `SERVER_INSTRUCTIONS` + pin test.
- **`kengram-cli`** — `Rescope` subcommand (wiring precedent: `backup.rs`'s standalone module).
- **`kengram-core`** — none. `Scope` already exists; outcome types live with storage.
- **No config delta.** Tag requeue uses the already-configured tagger model id (same resolution as `capture`).

## Derived-layer impact

- **Embeddings / retrieval:** none — the vector and trigram legs never read scope; `scope`/`scope_prefix` filters see the new value immediately after commit.
- **`list_scopes` / `stats` / web scope-browser:** live aggregates over `thoughts.scope`; counts migrate with the rows, zero changes.
- **Tag vocab conditioning:** per-scope top-N vocab shifts live for both old and new scopes — that's live re-derivation working as designed, not staleness. The staleness that *is* real (existing tags on the moved thought) is fixed by the requeue.

## Success criteria

1. **Single rescope round-trip.** `kengram rescope --thought <id> --to work.bar` moves the thought; exactly one `scope_changes` row appears (`actor='manual'`, reason recorded) carrying the *pre-update* `old_scope`; a re-run reports no-op and adds no rows; a bad thought id yields a clean not-found **distinct from** the no-op.
2. **Subtree rename.** `--scope work.foo --to work.bar` moves `work.foo` and `work.foo.baz`, never `work.foobar`; one audit row per moved thought, each carrying **that thought's own pre-rename scope** — the direct guard against the PG 16 trap that `UPDATE ... RETURNING` yields new values; `--dry-run` prints match count + requeue count and commits nothing.
3. **Escaping and offsets.** Renaming a `_`-bearing scope (`personal_medical → personal_health`) matches exactly *and* the resulting scope strings are correct — proving the raw prefix (mapping offset) and the escaped prefix (LIKE pattern) stayed separate parameters.
4. **Guards fail up front.** `--scope X --to X` and `--scope work --to work.archive` are usage errors before the first write: nothing moved, no audit rows, no queued jobs. Re-running any *legal* subtree rename stays a no-op indefinitely — self-nesting renames are rejected, not merely documented.
5. **All-or-nothing.** A rename whose mapping overflows 256 chars on some row (or would produce an invalid scope) rolls back the whole transaction: no partial moves, no audit rows, no queued jobs. A crash at any statement leaves the same clean state — scope update, audit, and requeue are one transaction.
6. **Tag re-conditioning, live thoughts only.** After the worker drains, the moved thought's `tags_extractor_*` provenance refreshes, and `strip_scope_identifiers` now strips the *new* own-scope identifier from entities (spot-check a thought whose old-scope name appears as an entity). Retracted thoughts moved by the same rename get audit rows but **no** `pending_tags` rows.
7. **MCP parity + actor.** `rescope_thought` returns `changed: false` at target and a clean not-found error otherwise; a supplied `actor` lands verbatim in `scope_changes`, absent → `mcp`; `/api` reads of the same thought (via `get_thought` orchestrators) match the MCP view.
8. **Operator-visible movement.** `kengram stats` per-scope summary and `list_scopes` reflect the rename; an emptied old scope disappears from `list_scopes`.
6. **The contract holds in code.** The only `UPDATE thoughts SET` touching `scope` anywhere in the workspace is inside the two rescope helpers; no code path writes `content`/`source`/`created_at`. (Grep + review at implementation.)

## Open questions

The first two below are **plan-time rulings**: whoever writes the implementation plan must decide them, not discover them mid-implementation.

- **`get_thought` / web-detail surfacing.** The retraction precedent says the audit path should surface the change — options: a `rescoped_at` + prior-scope hint on the thought shape, vs. full history staying SQL-only (like `migration_audit`). Leaning: surface "last rescope" metadata, keep history in SQL.
- **Tier 2 interaction.** Should a token locked to `work.*` be allowed to `rescope_thought` a `personal.*` thought? Today scope restrictions govern reads, not writes. Defer to the Tier 2 auth milestone, but the answer must land before Tier 2 ships — mirrored into `m7-operational-maturity.md`'s Tier 2 scope bullet and success criterion 2 so it can't be lost in planning.
- **`reason` policy.** Optional everywhere, or required for subtree renames (blast radius)?
- **`metadata` column.** Same third class as scope, but it feeds the finalize seam (`metadata.decision_type` override) and nothing rules on its mutability. Explicitly left unadjudicated here — worth a ruling before any future tool touches it.
